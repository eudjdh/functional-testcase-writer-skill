# 功能覆盖与优先级策略

## 优先级定义

| 级别 | 定义 |
|:---:|:---|
| P0 | 核心路径，阻塞发布 |
| P1 | 重要功能，影响体验 |
| P2 | 一般场景，建议执行 |
| P3 | 边缘场景，资源允许时执行 |

## 最低覆盖要求

每个功能点至少覆盖：

- 1 条核心**正常流程**（P0）。
- 1 条主要**异常处理**（P0 或 P1）。
- 1 条**边界情况**（P1 或 P2）。

## 子能力拆分清单

大功能点按下列维度拆分用例，避免遗漏：

- 入口与可达性：入口位置、入口可见条件、无权限时的入口表现。
- 表单：必填校验、格式校验、长度限制、默认值、清空。
- 状态：加载中、空状态、成功、失败、禁用、只读。
- 列表：排序、筛选、分页、搜索、空结果、超量。
- 详情：展开 / 折叠、内容完整、字段对应。
- 上传：类型限制、大小限制、多选、移除、失败重试。
- 导出：可导出条件、导出内容、导出入口可用性。
- 删除：二次确认、取消、删除后刷新。
- 提示与反馈：成功提示、错误提示、Toast、对话框。
- 刷新与恢复：刷新后状态、返回后状态、重复提交。

## 用例质量要求

- 一条用例只验证一个明确目标，不合并多个目标。
- 不堆数量；每条用例应能独立判定通过 / 失败。
- 操作步骤可复现，输入数据具体（给出示例值或明确占位）。
- 预期结果可观察、可判定，避免“正常显示”“符合预期”这类空泛描述。

## 不编造原则

- 页面观察只能说明“现在页面有什么”，不能自动当作产品应有行为。
- 需求不明确时，标注「待确认」或向用户询问，不自行臆断。
