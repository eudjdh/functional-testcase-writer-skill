# 与 playwright-ui-mapper 的衔接

本 skill 只产出功能测试用例文档；页面探索与可执行测试由 `playwright-ui-mapper` 负责。

## 上游输入

功能用例所需的页面事实可来自：

- `playwright-ui-mapper` 产出的 `page-map.yaml`（页面元素、语义定位、可见状态）。
- `flows/*.flow.yaml`（已确认的用户流程与成功标准）。
- 浏览器探索快照（角色、名称、标签、按钮文案）。
- 用户提供的需求说明、菜单结构、模块划分。

## 转换规则

| 上游 | 转为功能用例的哪个部分 |
|:---|:---|
| page-map 元素（按钮 / 输入框 / 链接 / 标签） | 候选操作对象、入口、可点击项 |
| page-map 变体（variant / 权限可见性） | 权限与可见性相关的用例 |
| flow 步骤 | 候选正常流程路径 |
| flow 断言（用户可见部分） | 预期结果 |
| 空状态 / 加载状态 / 错误状态 | 状态类用例 |
| 上传 / 导出 / 删除入口 | 对应子能力用例 |

## 边界

- **locator 不写入用例文档**：用例文档面向人，不写 `getByRole`、`nth()`、`href` 等。
- **页面观察 ≠ 产品预期**：观察到的当前行为不能自动当作“应该如此”。
  预期应来自需求、流程文件或用户确认。
- **预期不明确时**：写「待确认」或向用户提问，不编造。

## 反向衔接（可自动化）

文档生成后，可挑选可自动化的用例交回 `playwright-ui-mapper`：

- 优先 `P0 / P1` 且属于 `正常流程` 或 `边界情况` 的用例。
- 安全边界为 `read-only` 或 `isolated-write`。
- 每个可自动化用例映射为一个 flow，再生成 Playwright spec。
- 执行结果回填到用例的 `实际结果` 与 `测试记录`。

## 职责划分

| 工作 | 归属 |
|:---|:---|
| 探索页面、页面地图、漂移检测 | playwright-ui-mapper |
| 生成 / 执行 Playwright 测试 | playwright-ui-mapper |
| 功能测试用例文档、编号、INDEX | functional-testcase-writer |
| 安全 / 性能用例 | 其它专项 skill 或人工 |
