# 编号规则

## 前缀

| 类型 | 前缀 | 示例 | 本 skill 是否生成 |
|:---|:---|:---|:---|
| 功能点 | `FEAT-模块缩写-序号` | FEAT-AUTH-001 | 是 |
| 功能用例 | `TC-模块缩写-序号` | TC-AUTH-001 | 是 |
| 安全测试 | `SEC-模块缩写-序号` | SEC-AUTH-001 | 否（仅表头） |
| 性能测试 | `PERF-模块缩写-序号` | PERF-AUTH-001 | 否（仅表头） |

## 序号规则

- 序号为**三位数**，从 `001` 起。
- **模块内全局连续**：同一模块内的 `TC` 从 `001` 起，跨功能点文件连续递增，
  不随每个文件重新从 `001` 开始。
  - 例：`FEAT-AUTH-001` 用 `TC-AUTH-001 ~ 012`，则 `FEAT-AUTH-002` 从
    `TC-AUTH-013` 续编。
- **前缀固定为模块缩写**：功能用例统一用所属模块的缩写，不使用功能点自己的缩写。
- **无缺号、无重号**：新增用例接在现有最大序号之后。

## 生成前必做

1. 确认模块缩写（读取目标仓库的 `模板/testcase-convention.md` 或 `README.md`）。
2. 扫描该模块目录下所有 `FEAT-*.md`。
3. 用正则 `TC-[A-Z]+-(\d{3,})` 提取现有 `TC` 编号，取最大值。
4. 新用例从 `最大值 + 1` 开始，按三位数格式补零。
5. 功能点序号同理：用 `FEAT-[模块缩写]-(\d{3,})` 取最大值续编。

## 安全 / 性能

- 本 skill 只保留空表头，**不生成 `SEC` / `PERF` 编号**。
- 空表头不计入 `INDEX.md` 统计。
- 用户明确要求补充安全 / 性能用例时，才按同样规则编号。

## 引用同步

- 若「问题跟踪」「测试记录」引用了用例编号，重排后需一并更新。
- 调整或删除用例后应顺移补齐，保持连续。
