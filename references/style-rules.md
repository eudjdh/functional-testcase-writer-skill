# 文档与字段风格

本文件定义功能测试用例文档的固定风格。生成任何文档前先读本文件。

## 文件组织

- 每个**功能点**对应一个 `.md` 文件。
- 文件名：`FEAT-[模块缩写]-[序号]-[功能点名称].md`。
- 目录按产品业务模块划分，与目标仓库既有目录结构保持一致。

## 文档骨架

```md
# 测试用例 — [功能点名称]

---

> **功能点编号**：FEAT-XXX-001
> **功能点名称**：
> **所属模块**：
> **关联需求**：
> **测试范围概要**：
> **文档版本号**：V1.0
> **编写人**：
> **审核人**：
> **审批人**：
> **测试环境说明**：
> **编号提示**：TC 按模块内全局连续编号；安全 / 性能仅保留表头，默认不编号。

---

## 一、功能测试
（前置条件 / 测试数据 / 功能测试用例）

## 二、安全测试
（仅空表头）

## 三、性能测试
（仅空表头）

## 测试记录
## 问题跟踪
```

## 头部元信息

- 使用引用块 `>` 逐行列出，字段名加粗并以全角冒号 `：` 结尾。
- 除 `编写人 / 审核人 / 审批人` 可留空外，其余字段应填写。
- `功能点编号` 必须符合 `FEAT-[模块缩写]-[三位序号]`。

## 用例表格式

- 每条用例独立成一个「项目 / 内容」两列表。
- 表头固定为 `| 项目 | 内容 |`，分隔行 `|:---|:---|`。
- 用例之间空一行。
- 字段顺序固定：

| 项目 | 内容 |
|:---|:---|
| 用例编号 | TC-XXX-001 |
| 用例名称 |  |
| 用例类型 | 正常流程 |
| 输入条件 |  |
| 操作步骤 | 1.  |
| 预期结果 |  |
| 优先级 | P0 |
| 状态 | 待执行 |
| 实际结果 |  |

## 用例类型

仅允许三种：

- `正常流程`
- `异常处理`
- `边界情况`

## 操作步骤写法

- 用编号句：`1. ... 2. ... 3. ...`，步骤之间可用 `<br>` 换行或直接空格分隔（与目标仓库保持一致）。
- 只写**用户动作**：点击、输入、选择、上传、拖动、切换、滚动、刷新、查看、关闭、返回。
- 不写系统内部动作（发请求、写库、调用服务）。

## 预期结果写法

- 只写**用户可见反馈**：页面跳转、提示文案、按钮状态、弹窗开关、列表增减、字段展示、空状态。
- 提示文案用引号原样给出，例如：页面提示“用户名或密码错误，请检查后重试”。
- 不写接口返回码、后端状态、日志内容。

## 实际结果写法

- 未执行：留空或写 `待执行`。
- 已执行：写用户实际观察到的可见结果，可与预期一致或不一致。
- **禁止编造**：没有真实执行不得填写。

## 禁用词（功能测试章节内）

以下词不应出现在功能用例的操作步骤或预期结果中：

```text
接口 / API / 请求 / 响应 / 返回 200 / 返回码 / 数据库 / 后端 / 服务端 / 日志 / 函数 / 字段名 / SQL / JSON
```

> 例外：确属用户可见的“接口”字样（如页面上的按钮文案）可保留，但应尽量避免。

## 语言

- 正文使用简体中文。
- 技术缩写保留英文：`FEAT`、`TC`、`SEC`、`PERF`、`P0`~`P3`。
